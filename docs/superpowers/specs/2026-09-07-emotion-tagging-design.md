# 可扩展歌曲情绪标签体系：设计说明

## 目标

对正式比赛提供的任意情绪标签清单进行多标签打标。在每个标签精确率不低于 95% 的前提下，尽量提高覆盖率，并降低新增标签、重跑与人工复核成本。

首批验证标签为：热血、活力、治愈、思念、孤独。它们只是验收样例，不写死在系统逻辑中。

## 输入

- 歌曲元数据：歌曲 ID、标题、艺人、专辑、语种和时长。
- 音频：完整歌曲或可用音频片段。
- 歌词：完整歌词及可选的时间戳。
- 官方标签定义：标签名称、业务定义、适用范围、排除条件和相邻标签边界。
- 少量人工金标：用于标签阈值校准、评测和回归。

PMEmo 仅用于原型验证：它提供副歌音频、歌词、效价/唤醒度标注和评论，但不构成正式业务标签真值。

## 体系结构

### 1. 歌曲特征库

每首歌曲只提取一次可复用的特征：

- 音频嵌入及分段特征：能量、速度、动态变化、人声与编曲表现。
- 歌词嵌入及段落特征：主题、意象、情绪对象、否定与叙事转折。
- 基础元数据：语种、时长、是否纯音乐、歌词和音频质量状态。

特征与生成模型版本绑定，新增标签只复用特征，不重复分析整首歌。

### 2. 标签卡

每个官方标签编译为一张版本化标签卡，包含：

- 业务定义与必要条件；
- 正例、反例、易混淆标签；
- 歌词和音频的证据描述；
- 模态冲突规则；
- 校准后的自动放行阈值。

标签卡是新增标签的唯一配置入口。

### 3. 双证据候选与融合

系统分别产生歌词分数、音频分数和可读证据；融合器同时参考模态一致性、语种、数据完整度和标签卡规则。

- 高置信且证据一致：自动放行。
- 单模态强证据或接近阈值：进入低成本模型复核。
- 模态冲突、证据不足或新类型：进入人工裁定队列。

输出为多标签候选，不强制为歌曲分配唯一情绪。

### 4. 校准、评测与迭代

每个标签分别保留训练、校准和隔离评测样本。选择能让校准集精确率不低于 95% 的最低放行阈值，以最大化覆盖率。

生产结果持续随机抽检。人工裁定的冲突样本、误标样本和新类型样本进入困难样本集；每次更新标签卡、模型或阈值必须在固定回归集上重新验收。

## 首期原型

基于 `F:\netease\_music\PMEmo\data_2019\extracted\PMEmo2019`：

1. 合并元数据、静态效价/唤醒度、歌词与评论可得性。
2. 生成五个验证标签的候选集，而非最终标签。
3. 输出每个候选的音频证据、歌词证据、冲突状态和人工复核优先级。
4. 统计覆盖率、候选量、缺歌词比例和待复核量。

效价/唤醒度只用于候选排序。例如高唤醒、正效价可支持“活力”候选；“思念”和“热血”必须依赖歌词或更具体的音频证据，不能只由二维情绪值推断。

## 验收标准

- 新增正式标签时，不修改共享特征生成和融合主流程。
- 每个标签的结果均保留可复核证据和版本信息。
- 在隔离评测集上，逐标签报告精确率、覆盖率、样本数与成本。
- 只有达到标签精确率门槛的自动结果才进入生产输出。

## 限制

PMEmo 的 794 段副歌以英文流行歌曲为主，且完整歌词仅覆盖其中 629 首；它只能验证处理链路，不能证明正式中文曲库或完整业务标签的效果。正式训练、评测和生产必须以比赛方授权的数据与标签定义为准。
