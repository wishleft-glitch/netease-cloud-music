# 情绪标签服务：正式协议升级设计

**日期：** 2026-09-10  
**状态：** 已确认，待实施

## 背景与目标

正式资料将评测协议更新为公司内网可访问的 HTTP/1.1 同步服务。评测请求提供带签名的音频 URL、歌曲元数据与多种歌词字段；服务必须在 30 秒内完成下载、推理与响应。评分以 Top-1 为核心，同时计算 15 个二级标签的宏召回；宏召回低于 80%、单次成本高于 0.1 元或服务不稳定时不能进入排名。

本次升级目标是把现有本地歌词基线改为严格符合正式协议的同步服务，并使用 `情绪歌曲导出_20260910.xlsx` 重新建立可复跑的训练、验证与交付证据。服务输出一个最置信的二级情绪，同时返回第二候选和真实、可审查的判定证据。

## 选择与边界

采用**同步模式**：评测方调用 `POST /api/v1/emotion/recognize`，单次请求在 25 秒内部预算内完成，以保留网络和评测端余量。同步模式减少队列、状态保存和轮询复杂度，适合单曲最长十分钟的音频输入及 5 QPS 的评测负载。

服务不使用未验证的远程模型调用作为唯一依赖。当前本地文本模型是可用降级路径；音频只在下载、格式和预算均满足条件时使用。音频失败时保留歌词路径，不能伪造音频证据。若请求本身无可判定信息或发生内部错误，返回规范 JSON 错误体，不编造标签。

## API 契约

### 请求

请求路径为 `POST /api/v1/emotion/recognize`，`Content-Type: application/json`，UTF-8。

必填字段：

- `audio_url`：HTTP/HTTPS 的带签名 mp3/m4a URL。
- `song_name`：歌曲名称。
- `song_id`：曲库歌曲 ID。

可选字段：`album_name`、`artists`、`text_lyric`、`lrc_lyric`、`lrc_translation`。所有歌词字段允许为空或 null；文本总长度设置防御性上限，超过上限返回参数错误。

服务直接下载请求传入的音频。下载器保留现有的重定向、超时、大小限制和 SSRF 防护。生产环境中的代理属于部署方显式配置，仅可用于精确配置的可信音频域名，绝不从环境变量隐式读取。

### 成功响应

成功时始终返回：

```json
{
  "code": 200,
  "data": {
    "top_emotion": "狂欢",
    "top_confidence": 0.8735,
    "second_emotion": "活力",
    "second_confidence": 0.1024,
    "evidence": "歌词呈现鼓舞与向上主题；音频节奏能量较高。",
    "cost_ms": 4210
  },
  "error": ""
}
```

Top-1 和 Top-2 必须是配置的 15 个标签；两者不同，置信度为 [0, 1] 且保留四位小数，第二候选不高于第一候选。`evidence` 不超过 500 字，只说明本请求中实际参与判定的歌词片段、音频测量或模型证据，不能声称未获得的音频或外部事实。`cost_ms` 使用服务端单调时钟计算完整调用耗时。

参数错误返回 `{"code":400,"message":"..."}`；下载、解码和内部错误使用合适的 4xx/5xx JSON 错误体，不返回虚构标签。

## 推理链路与超时

总服务内部预算为 25 秒：

1. 参数校验、歌词规范化和本地文本预测。
2. 在配置允许时安全下载与解码音频；每个阶段有独立上限，且整体不可超时。
3. 生成音频特征或后续经离线验证有效的音频表征；无效 URL、HTML 响应、下载或解码失败均记录为降级原因。
4. 融合实际可用的证据，按确定的标签顺序打破并列，输出 Top-1、Top-2 与证据。

现有 4 个基础声学特征尚未在试跑中表现出增益，因此不会直接纳入生产融合。未来仅在独立验证集证明对宏召回或 Top-1 有增益后启用音频分支。

## 数据、训练与验证

使用正式更新表 `情绪歌曲导出_20260910.xlsx` 作为本轮唯一训练输入。按 `song_id` 分组分割，任何一首歌曲不会同时出现在训练与验证中。保留一份不参与模型选择的锁定测试集；开发比较在另一份固定开发切分中进行。

自测报告至少包含：

- Top-1 准确率、Top-2 命中率；
- 15 标签宏召回及逐标签召回；
- 单标签和多标签训练注释对应的清晰分母；
- 音频下载、可解码和降级比例；
- 请求 P50/P95/P99、错误率和单次成本估算。

隐藏集中的边界和混合情绪歌曲不以记忆训练数据的方式处理；证据输出与置信度用于支持人工复核。

## 部署与运维

服务支持绑定内网 IP 或内网域名，不使用仅 localhost 的默认交付配置。提供启动、健康检查和重启脚本；健康接口不泄露模型路径、数据或凭据。日志仅记录请求 ID、耗时、阶段状态、错误类别和资源指标，不记录带签名 URL、完整歌词或令牌。

交付包包含完整代码、依赖锁定、模型资产说明、成本估算、架构图、部署步骤、监控项与至少五条故障排查项。
