# 情绪比赛方案纠偏与实测计划

目标：全样本输出一个二级标签，争取 Top-1 95%，同时满足 macro recall >=80%、每次 <=0.10 元和同步 30 秒时限。指标不能用 Top-K 覆盖或小比例放行准确率替代。

用户已持续授权直接评估、实验和优化，无需重复询问是否开始。实施使用方案评审、writing-plans、系统排查和并行审查流程。

## 设计与取舍

1. 修正评估可信度。历史固定 Test 被多次用于选参，只能作为历史回归集；公开训练样本重新划分不能宣称是未见的盲测。候选参数只能在 Train 内 Dev 选取，完整披露已暴露数据的限制。
2. 音频重新做有效对照。使用同一组歌曲比较全 Train 训练的 v9 和音频融合；先审查 15 秒前奏、下载失败和预处理，避免因实现局限否定音频模态。
3. 本地语义候选。用官方来源的小型量化生成模型和完整 15 类业务定义对 Dev 做探针；无需假设用户有内网大模型接口。先测时延与格式，再做分层样本对照。若性能差，保留可复现实验并拒绝晋级。
4. 修复 Rubric 中偏离命题方定义的内容，版本化变更并验证 evidence 不伪造。

继续只调 TF-IDF 的成本低但不足以解释目标差距；全面微调大模型耗时与硬件要求高。本轮采用“修复评测 + 音频公平对照 + 本地量化语义探针”，按实测决定晋级，避免将方案文字当成模型增益。

## 验证约束

生成器只接收歌词、元数据、业务定义和训练检索样例，不能接收待评估样本答案。失败请求计入覆盖/宏召回，不只统计成功样本。不能用全量重训的服务模型在旧 Test 上报告泛化。费用缺少计费参数时仅报告资源与时延，不编造单曲人民币成本。最终 95% 须由独立未参与开发的评测证明。
